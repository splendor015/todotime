# TodoTime

## 标签与多日背景

- 常用标签：课程、运动、吃饭、工作、学习、休息、出行、家务。日程编辑面板可点击彩色预设；仍可输入多个自定义标签。预设标签在日历中的标记沿用对应颜色。
- 全天日程可开启“多日背景安排”，其起止日期之间的日期格会铺上对应标签的浅色背景，日程本身仍保留在当天列表，普通安排也照常显示。
- 可选“忽略这条安排与当天任务的冲突提示”。它只将该背景日程排除出冲突检测；不会隐藏其他安排，也不会关闭其他任务之间的冲突检测。
- 新的背景属性通过 SQLite 增量迁移加入，不需要清空数据库或已有任务。

## 节假日调休（尚未接入）

可以同步，但国务院每年公布的放假安排包含“假期日期”和“调休工作日”，不能只用周末或国外节假日日历代替。接入前应选择数据源，并定义更新责任：

1. 以国务院办公厅每年发布的官方通知为权威来源；可人工录入，也可审核后导入数据文件，稳定性和准确性最好。
2. 可接第三方中国节假日 API，自动化更高，但需评估可用性、授权、限额及数据错误时的回滚。
3. 导入后在日历上区分法定假日、调休补班日；只做背景标记，不自动增删用户日程。

第一版比较稳妥的是每年官方安排发布后由管理员确认并导入；若后续要自动更新，保留官方校对入口和手动修正能力。

双人共享时间规划日历。当前版本包含：用户名密码登录、首位用户管理员、最多两位成员、周视图和月视图日历、全天/待安排任务、跨天时间段、每天/每周/每两周/每月重复任务、私人任务遮罩、拖拽调整、评论、站内通知、浏览器通知、回收站和管理员重置密码。页面每 5 秒自动同步当前视图数据。

## 本地运行

要求 Node.js 18+（推荐 Node.js 20）。

```bash
npm install
npm run dev
```

浏览器打开 `http://localhost:5173`。第一个注册用户自动成为管理员，第二个注册用户成为成员；达到两位后注册会自动关闭。

生产模式：

```bash
npm run build
NODE_ENV=production JWT_SECRET='请替换为随机长字符串' npm start
```

生产服务默认监听 `3030` 端口。SQLite 文件位于 `data/todotime.sqlite`，请定期备份整个 `data` 目录。

## Docker 部署

先在项目目录创建仅服务器持有的 `.env`（该文件已被 Git 忽略）：

```dotenv
JWT_SECRET=请替换为随机长字符串
TODOTIME_PUBLIC_URL=https://todotime.me
XTUIS_TOKEN=第一个虾推啥令牌
XTUIS_TOKENS=其他虾推啥令牌，多个用英文逗号分隔
XTUIS_USERNAME=接收通知的TodoTime用户名
```

随后构建并启动：

```bash
docker compose up -d --build
```

服务仅绑定宿主机 `127.0.0.1:3030`，数据库通过 Docker volume `todotime-data` 持久化。由宿主机上的 Caddy/Nginx 反向代理到该端口并提供 HTTPS。

## 重要说明

### 时间重叠与冲突提醒

- “同一负责人被重复安排”：两项日程的实际负责人有交集且时间重叠，红色警示。
- “双方时间重叠”：两项日程分别由不同成员负责，蓝色协调提示，不视为冲突。负责对象按创建者解析，包含“对方负责”和“共同负责”。
- 只检查未完成、未删除且同时有开始与结束时间的日程，包含全天、跨天和重复日程。首尾相接不算重叠；待安排、仅开始或仅截止的任务不推测时长。
- 保存、拖拽、恢复等操作后返回检查结果；检查范围为所选日期起 90 天。日历中的“时间检查”另外检查当前周／月全部日程，不受搜索和成员筛选影响。旧日程无需重新创建也能在当前视图看到提示。
- 新检测到的重叠会给双方写入站内通知（包括操作者）；同一任务对的重复日程合并提醒，相同负责人和时间的重叠不会因刷新、改标题而重复通知。历史通知是保存当时的快照，当前情况以日历检查为准。
- 私人安排在对方的检查列表中只显示“私人安排”；新的重叠通知仅包含时间和类型，不包含任务标题、备注。
- 浏览器系统通知需打开页面、使用 HTTPS 或 localhost 并授予通知权限（点击“通知”时可授权），还受系统通知设置限制。另一位成员在线时通常在下一轮 5 秒同步后看到更新；关闭页面后浏览器自身不会继续推送。
- 可通过“虾推啥”公众号接收微信通知。复制 `.env.example` 为 `.env`，设置 `XTUIS_TOKEN` 和对应的 TodoTime `XTUIS_USERNAME` 后重启服务；更多接收端可写入 `XTUIS_TOKENS` 并用英文逗号分隔。日程动态、评论、冲突及临近开始提醒会同时保留站内通知并分别排队推送到全部接收端，单个接收端发送失败不会影响其他接收端或日程保存。
- 新建或编辑有开始时间的日程时，可选择提前 10、30 或 60 分钟提醒。提醒任务持久化去重，服务重启后仍会继续检查；全天任务和待安排任务不会发送临近提醒。
- 通知去重记录保存在 SQLite 中，启动时自动创建表，无需清空原有数据。已有日程的历史重叠不会在升级时批量补发通知。

### 验证

运行 `npm test` 执行冲突规则及真实 HTTP 接口测试，运行 `npm run build` 检查前端构建。接口测试使用独立临时数据库，不读写项目现有日程。

### 其他

- 时间按中国标准时间展示，数据库以 ISO 时间保存。
- 当前通知支持站内、浏览器和可选的虾推啥微信公众号推送；短信尚未接入。
- 密码找回采用管理员在“空间设置”中重置成员密码；没有邮箱或手机号验证。
- `npm run db:reset` 会删除本地 SQLite 数据库，仅用于开发验收。
